# PhysioTrack Backend

This is the Django REST API behind the PhysioTrack mobile app. It handles accounts with email verification and JWT authentication, and serves guided physiotherapy programs while tracking each user's progress step by step.

The mobile client lives in [PhysioTrack](https://github.com/kaancakr/PhysioTrack).

## Features

- **Email sign-up with verification codes.** Codes are 6 digits, stored hashed, expire after 10 minutes and allow 5 attempts. They are sent through the [Resend](https://resend.com) HTTP API or Django's email backend. An account can log in only after its email is verified.
- **JWT authentication** with SimpleJWT:
  - Access tokens last 15 minutes. Refresh tokens last 30 days and rotate on use, and the old token is blacklisted.
  - Logout blacklists the refresh token and increments a per-user `token_version` claim, which revokes access tokens that are still valid.
- **Rate limiting.** Signup, verification, resend, login and refresh are throttled per IP and/or per email. Authenticated users are limited to 120 requests per hour.
- **Patient profile.** Stores full name, focus area, weekly goal, age range, gender and daily step goal, which are collected at sign-up and editable later.
- **Programs and exercises.**
  - A program contains ordered exercises, and each exercise contains instruction steps.
  - Steps must be completed in order.
  - The API reports per-user progress at exercise, program and overall level.
- **Favourite exercises.** Each favourite gets suggested days of the week based on the user's weekly goal, plus current and longest streaks. A monthly calendar endpoint lists favourites by day.
- **Conditional GETs.** Program endpoints return an `ETag` and answer `304 Not Modified` when the request's `If-None-Match` matches.
- **API documentation.** An OpenAPI schema and Swagger UI are generated by drf-spectacular.
- **Seed command** for the default programs: neck, shoulder, lower back and knee.
- **Django admin** for users, profiles, verification codes, programs, exercises, completions and favourites.

## Tech stack

- Python 3.13+
- Django 4.2, Django REST Framework 3.16
- djangorestframework-simplejwt, with token blacklisting
- drf-spectacular for OpenAPI and Swagger UI
- PostgreSQL (psycopg2) at runtime, SQLite for tests
- python-dotenv
- Resend HTTP API for transactional email (optional)

## Project structure

```
config/
  settings_base.py     Shared settings: DRF, SimpleJWT, throttle rates, OpenAPI, logging
  settings.py          Runtime settings read from environment variables (PostgreSQL)
  settings_test.py     Test settings (SQLite, in-memory email backend)
  urls.py              /admin/, /swagger/, /api/
apps/core/
  authentication/      Sign-up, email verification codes, login, token refresh/logout, throttles
  users/               Custom email-based User model, Profile, /api/users endpoints
  programs/            Programs, exercises, step completion, favourites, seed data,
                       `seed_programs` management command
  views.py, urls.py    Health check, schema/docs, API routing
  models.py            Shared TimestampedModel
  pagination.py        Page-number pagination (page, page_size; max 100)
  openapi.py           Shared OpenAPI response definitions and renderers
tests/test_api.py      API integration tests
```

## API overview

All routes are under `/api/`. Authenticated endpoints expect `Authorization: Bearer <access token>`.

| Method | Path | Access | Description |
| --- | --- | --- | --- |
| GET | `/api/health/` | Public | Health check |
| GET | `/api/schema/` | Public | OpenAPI schema (also served at `/swagger/`) |
| GET | `/api/docs/` | Public | Swagger UI |
| POST | `/api/auth/signup` | Signed-out only | Create an account and email a verification code |
| POST | `/api/auth/verify-signup-code` | Signed-out only | Verify the code and return access and refresh tokens plus the user |
| POST | `/api/auth/send-signup-code`, `/api/auth/resend-signup-code` | Signed-out only | Send a new verification code |
| POST | `/api/auth/login` | Signed-out only | Log in with email and password and return tokens plus the user |
| POST | `/api/auth/token/refresh` | Public | Exchange a refresh token for new tokens |
| POST | `/api/auth/logout` | JWT | Blacklist the refresh token and revoke issued tokens |
| GET | `/api/auth/me` | JWT | Current user, profile and overall progress |
| GET, PATCH, PUT | `/api/users/me/` | JWT | Read or update the current user's profile |
| GET | `/api/users/` | Admin | List users (`search`, `is_active`, `is_staff`, paginated) |
| GET | `/api/users/<uuid>/` | Admin | Get a user by public ID |
| GET | `/api/programs/` | JWT | Active programs with progress (`search`, `focus_area`, paginated) |
| GET | `/api/programs/all/` | Admin | All programs, including inactive ones |
| GET | `/api/programs/favorites/calendar/?year=&month=` | JWT | Favourite exercises grouped by day for one month |
| GET | `/api/programs/<id>/exercises/` | JWT | Exercises in a program, with progress |
| GET | `/api/programs/<id>/exercises/<exercise_id>/` | JWT | Exercise detail, including steps and progress |
| POST | `/api/programs/<id>/exercises/<exercise_id>/favorite/` | JWT | Add or remove a favourite, optionally with `days_of_week` |
| POST | `/api/programs/<id>/exercises/<exercise_id>/steps/<step_index>/complete/` | JWT | Complete the next step of an exercise |

Throttle rates are set in `REST_FRAMEWORK["DEFAULT_THROTTLE_RATES"]` in `config/settings_base.py`.

## Getting started

### Prerequisites

- Python 3.13+
- PostgreSQL
- [uv](https://docs.astral.sh/uv/) (recommended; `pyproject.toml` contains a `[tool.uv]` section) or pip

### Install

```bash
uv sync
```

Or with pip:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e .
```

### Configure

Create a `.env` file in the repository root. `config/settings_base.py` loads it with python-dotenv, and it is git-ignored. `manage.py` uses `config.settings` by default.

| Name | Required | Purpose |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | Yes | Django secret key |
| `DJANGO_DEBUG` | No | Boolean (`true`/`false`, `1`/`0`, `yes`/`no`, `on`/`off`). Defaults to false. |
| `DJANGO_ALLOWED_HOSTS` | No | Comma-separated hosts. Defaults to `127.0.0.1,localhost`. |
| `POSTGRES_DB` | Yes | Database name |
| `POSTGRES_USER` | Yes | Database user |
| `POSTGRES_PASSWORD` | Yes | Database password |
| `POSTGRES_HOST` | Yes | Database host |
| `POSTGRES_PORT` | Yes | Database port |
| `PHYSIOTRACK_EMAIL_PROVIDER` | Yes | `resend` (Resend API) or `django` (Django email backend) |
| `RESEND_API_KEY` | Yes | Resend API key. Required by settings even when the provider is `django`. |
| `RESEND_FROM_EMAIL` | Yes | Sender address for verification emails, used by both providers |
| `EMAIL_BACKEND` | No | Django email backend path. With the `django` provider it defaults to the console backend. |

For local development, set `PHYSIOTRACK_EMAIL_PROVIDER=django`. Verification codes are then printed to the console instead of emailed.

### Migrate, seed and run

```bash
uv run python manage.py migrate
uv run python manage.py seed_programs      # load the default exercise programs
uv run python manage.py createsuperuser    # optional, for /admin/
uv run python manage.py runserver
```

If you installed with pip, drop the `uv run` prefix. Once the server is running, the Swagger UI is at `http://localhost:8000/api/docs/`.

### Run tests

The integration tests in `tests/` use Django's test runner and DRF's `APIClient`. The test settings use SQLite and an in-memory email backend, so PostgreSQL and a `.env` file are not needed.

```bash
uv run python manage.py test tests --settings=config.settings_test
```
